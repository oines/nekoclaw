# 这是什么

一套让 AI 角色真正"活在"聊天软件里的系统。

它不是普通的聊天机器人。普通机器人每次对话都从零开始，不记得你是谁，不会主动联系你，在群里也只会机械地回答问题。这套系统解决的是另一个问题：**让 AI 角色像一个真实的人一样存在于你的社交环境中。**

---

## 它能做什么

**记住你**
每次对话结束后，它会自动整理这次聊了什么、了解到了什么，写进自己的记忆里。下次见面，它记得你的名字、你们聊过的事、你的喜好和情绪状态。不是假装记得，是真的记得。

**主动联系你**
它不只是等你发消息。你可以让它在特定时间主动给你发消息，比如早上提醒你、定期分享内容、在合适的时机关心你。

**在群里有存在感**
它可以在群组里安静地观察，不打扰大家。但它一直在听，知道群里在聊什么。被问到的时候，它能回答"刚才你们在讨论什么"。它也知道什么时候该说话、什么时候该沉默。

**同时活在多个平台**
同一个角色可以同时在 Telegram 和 QQ 上运行，记忆是共享的。你在 QQ 认识它，在 Telegram 再遇到，它还是同一个它。

**有自己的技能**
它可以查天气、查信息、生成图片、调用各种外部服务，然后把结果发给你。这些技能可以按需扩展。

---

## 记忆是怎么工作的

这是整个系统最核心的部分，也是它和普通 AI 最不一样的地方。

### 记忆的五个层次

每次它开口说话之前，都会把下面这些内容依次装进脑子里：

**第一层：人格（SOUL.md）**
存放在工作区根目录的 `SOUL.md` 文件，用自然语言写成，描述这个角色的性格、说话风格、价值观、行为边界。每次对话都完整注入，始终在场。这份文件可以手动编辑，Formation 和 Dream 都不会碰它，人格不会因为记忆整合而漂移。

**第二层：持久事实（MEMORY.md）**
存放在工作区根目录的 `MEMORY.md` 文件，记录它认为需要长期保留的事实——比如自己的身份背景、重要关系、特定偏好。这份文件由它自己在对话中维护，也可以手动编辑。每次对话都完整注入。

**第三层：记忆索引（.nekoclaw-persona/index.md）**
所有它认识的人和活跃过的场景（群组、频道）的简短摘要，每条条目都带着指向详细文件的路径，格式类似：
```
- Alice (memory/people/alice.md) — 老朋友，喜欢摄影，在 Telegram 主群认识
- 技术讨论群 (memory/scenes/telegram-group-123.md) — 主要聊编程和 AI
```
每次对话开始时都会看一眼，控制在 2,000 token 以内。这是它的"通讯录"，告诉它有哪些详细记忆可以调取。

**第四层：详细记忆（.nekoclaw-persona/memory/）**
每个人和每个场景各有一个独立的 Markdown 文件：
- `memory/people/alice.md` — 关于 Alice 的详细记录：性格、关系、共同经历、情感细节
- `memory/scenes/telegram-group-123.md` — 关于这个群的详细记录：氛围、常驻成员、话题倾向

这层**不会自动加载**。它在对话中看到索引后，自己判断是否需要读某个文件——比如用户提到了 Alice，它才会去读 `alice.md`。这样既保持了提示词轻量，又能在需要时获取完整背景。

**第五层：观察日志（.nekoclaw-persona/observations/）**
每个场景对应一个 `.log` 文件，记录它在这个群里看到的所有消息，格式如下：
```
[2024-01-15T09:23:11Z] telegram:user_123 Alice: 下周我要去北京出差
[2024-01-15T09:24:05Z] telegram:user_456 Bob: 那正好，我也在北京
```
即使它没有参与，消息也会被记录。每次对话时会把最近的观察（最多 80 行，约 1,200 token）注入上下文，让它知道"最近这里发生了什么"。这是原始见闻，Formation 处理后会从头部移除已消化的行。

这五层叠加在一起，构成了它在每次开口前的完整认知状态。

### 记忆是怎么形成和整合的

原始观察不会自动变成记忆。系统用两个独立的机制来完成这件事：**Formation（形成）** 和 **Dream（梦境整合）**。

#### Formation：消化刚发生的事

**触发时机：** 每次对话结束后，如果这个场景的观察积压超过 50 条，或者最旧的观察已经超过 30 分钟没有处理，就会自动触发。

**它能看到什么：**
- 本轮用户发的消息原文
- 它自己实际回复的内容
- 这个场景的完整观察日志
- 现有的记忆索引和场景记忆文件（主动读取）

**它看不到什么：** 完整的会话历史、其他场景的观察、人格文件。Formation 是场景局部的，只处理当前这个群或对话的信息。

**它会操作哪些文件：**
- `index.md` — 更新本场景相关的人物/场景条目
- `memory/people/*.md` — 编辑已有人物文件，或在需要时新建
- `memory/scenes/{当前场景}.md` — 编辑本场景记忆，或在不存在时新建

**它不能做什么：** 不能删除任何文件。处理完的观察行会从日志里移除（消费掉）。

**运行方式：** 异步，在后台悄悄进行，用户不需要等待。

---

#### Dream：整理所有记忆、建立全局认知

**触发时机：** 每 6 小时检查一次，如果记忆语料库的内容自上次 Dream 以来有变化（通过文件签名判断），就会触发。

**它能看到什么：**
- `index.md` 完整内容
- 所有人物文件和场景文件（每个取前约 220 token 的摘录）
- 所有观察日志（每个取尾部约 180 token 的摘录）
- 各类文件的数量统计

是全局视角，但每个文件只看摘录，不是全文。

**它会操作哪些文件：**
- `index.md` — 全局重建，确保所有条目路径可寻址、跨场景一致
- `memory/people/*.md` — 编辑：跨场景合并同一人的认知、压缩过时内容
- `memory/scenes/*.md` — 编辑：压缩低价值内容
- 新建 `memory/people/*.md` — 当某人在多个场景被反复提及但尚无独立文件时
- 删除低价值文件 — Dream 独有的权限，但必须先更新 `index.md` 保持引用一致

**它不做什么：** 不消费观察日志——读取观察作为参考，但不移除任何行。不碰 `SOUL.md` 和人格文件。

---

#### Formation 和 Dream 的对比

|  | Formation | Dream |
|--|-----------|-------|
| 触发方式 | 每轮对话后，观察积压达到阈值 | 每 6 小时，语料库有变化 |
| 视野范围 | 单个场景 | 全部场景 |
| 携带的上下文 | 本轮消息 + agent 回复 + 场景观察 | 所有记忆文件的全局快照 |
| 能否删除文件 | 不能 | 可以 |
| 观察日志 | 消费（处理完的行被移除） | 只读，不消费 |
| 核心目标 | 把这次对话的新信息写进记忆 | 跨场景整合、重建索引、清理冗余 |
| 失败处理 | 最多重试 3 次，超限丢弃观察 | 记录错误状态，下次重试 |

两个机制分工明确：Formation 负责"消化"，Dream 负责"整合"。Formation 跑得频繁但视野窄，Dream 跑得少但看得全。两者加在一起，让记忆不只是堆积，而是真正在成长和深化。

## 它的人格是怎么定义的

每个角色有一份"灵魂文件"（SOUL.md），用自然语言写成，描述这个角色的性格、说话风格、价值观、行为边界。

这份文件可以写得很细：它喜欢什么话题、讨厌什么、在什么情况下会拒绝回答、说话是温柔还是直接。这些设定会始终影响它的每一次回复，Formation 和 Dream 都看不到这份文件，人格不会因为记忆整合而漂移。

---

## 沉默也是一种选择

它不会对每条消息都回复。系统里有一个明确的"沉默"操作——它可以主动决定这次不说话。

这在群组场景里很重要。一个真实的人不会对群里每句话都接话，它也不会。它知道什么时候该参与、什么时候旁观就好。

---

## 任务队列与背压

每个 agent 有自己独立的任务队列，同一时间只处理一条消息，不会并发乱序。队列最多积压 50 条，超出后新消息会被拒绝并告知用户"我现在很忙"。

这保证了它的回复始终是有序的，不会因为消息涌入而产生混乱。

---

## 会话整洁

对话越来越长，塞进模型的内容就越来越多，最终会超出限制。系统会自动管理这个问题：

- 始终为模型的输出保留足够空间（20,000 token）
- 保留最近的对话历史（20,000 token）
- 对过长的工具执行结果先做软裁剪（保留头尾），实在太多再硬清除
- 最近 3 条 agent 回复始终受保护，不会被裁剪

用户感知不到这个过程，但它保证了无论对话多长，系统都能稳定运行。

---

## 它在哪些平台上运行

目前支持 **Telegram** 和 **QQ**。

同一套系统可以同时管理多个不同的角色，每个角色有独立的记忆和人格，互不干扰。

---

## 这套系统适合用来做什么

- 打造有真实感的 AI 陪伴角色
- 在社群里运营有人格的 AI 成员
- 给品牌或 IP 创建能长期互动的虚拟形象
- 探索 AI 与人类在真实社交环境中协作的可能性

---

## 它不是什么

它不是一个问答工具，不是客服机器人，也不是任务助手。

它是一个**在真实社交环境中持续存在、持续成长的 AI 角色**。
